# CQA — Conversation Quality Analytics

Прототип для оценки качества диалогов контакт-центра Freedom Broker. Можно настроить чек-лист и оценить по нему чаты и звонки на RU/KZ/EN. Дальше смотрим баллы с обоснованием и ссылками на реплики, подаём апелляцию по критерию и выносим решение проверяющего с пересчётом итога.

## Запуск

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env                      # вставьте ссылку GET из гайда организаторов в CQA_SOURCE_URL
export ANTHROPIC_API_KEY=sk-ant-...      # или без ключа: через установленный Claude Code (`claude -p`)
./run.sh                                  # http://127.0.0.1:8000
```

При первом старте создаётся чек-лист по умолчанию. Если есть локальный кеш `data/dev.json` (в git не входит), DEV-набор подгружается из него. Свежий набор, в том числе контрольный, загружается кнопкой **«Из API организаторов»** на странице «Диалоги»: укажите `group_id`. Запрос идёт через бэкенд, поэтому CORS не мешает.

Настройки (env):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | ключ Claude API |
| `CQA_BACKEND` | `auto` | `api` (по ключу), `cli` (через `claude -p`: те же промпт и JSON-схема, `--safe-mode` без CLAUDE.md и инструментов), `mock` (демо-заглушка, только явно); `auto` выбирает первое доступное, а без модели оценка не запускается |
| `CQA_CLI_PARALLEL` | `6` | сколько вызовов `claude -p` одновременно |
| `CQA_MODEL` | `claude-opus-5-5` | модель оценки |
| `CQA_EFFORT` | `high` | глубина рассуждения (`low` … `max`) |
| `CQA_SAMPLES` | `3` | сколько независимых прогонов на диалог (голосование по критериям) |
| `CQA_CONCURRENCY` | `8` | сколько диалогов оценивается параллельно |
| `CQA_PII_MASK` | `1` | маскировать персональные данные перед отправкой в модель (`0` — выключить) |
| `CQA_SOURCE_URL` | — | адрес API организаторов из гайда (секрет, только в `.env`), `group_id` подставляется сам |

## Тесты

```sh
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
```

Тесты идут на временной базе и мок-оценщике, поэтому ключ API, сеть и реальная модель не нужны. Что покрыто:
- формула итога по PDF: веса, ступени, перераспределение N/A, округление, флаг грубой ошибки;
- проверка ответа модели, голосование и пропуск третьего прогона;
- маскирование персональных данных;
- весь API: загрузка, версии чек-листов, оценка, апелляции с ручными баллами, точность, экспорт;
- синтаксис и импорты JS-модулей.

На GitHub тесты запускаются при каждом пуше (`.github/workflows/tests.yml`).

## Модель, точность и стоимость

Используется **Claude Opus 5.5** (`claude-opus-5-5`, $4 / $20 за 1M токенов на вход и выход) с adaptive thinking и `effort=high`. Ответ приходит строго по JSON-схеме.

Главный критерий отбора — близость к эталону (Ground Truth), поэтому точности подчинено всё:
- **Чек-лист организаторов как конфигурация.** 8 критериев, шкалы со ступенями 0/5/10/15/20 и 0/4/7/10, флаг «Грубые ошибки» без баллов. Памятка со стр. 3 PDF лежит в чек-листе и попадает в промпт.
- **Время считает код, а не модель.** Первая реакция оператора и ожидания дольше порога (3 мин) вычисляются по меткам времени и передаются модели как готовые факты.
- **Консенсус прогонов.** Каждый диалог оценивается `CQA_SAMPLES=3` раза параллельно, по каждому критерию берётся ответ большинства. При ничьей на шкале выбирается медианная ступень. Согласованность («консенсус 2/3») видна в карточке, а спорные критерии помечаются на проверку.
- **Проверка ответа.** Значение приводится к допустимой ступени, N/A принимается только там, где разрешён, номера реплик и цитаты сверяются с транскриптом.
- **Страница «Точность».** Загружаем эталон (JSON или CSV) либо отправляем проверенную человеком оценку кнопкой «В эталон». Система показывает совпадение по каждому критерию, среднюю ошибку итога и расхождения по диалогам. Так промпт настраивается до контрольного этапа.

Стоимость одной оценки (3 прогона): вход ≈ 3,5 тыс. токенов на прогон (правила и чек-лист кешируются), выход ≈ 2–4 тыс. Итого **≈ $0.15–0.30 за диалог**, ≈ $2–3 за 10 контрольных диалогов. С `CQA_SAMPLES=1` выходит примерно втрое дешевле. Фактическая стоимость, токены и время каждой оценки считаются из `usage` и показываются в карточке и на «Обзоре».

## Как устроено

```
frontend/              чистые HTML/CSS/JS, без сборки
  js/app.js            <cqa-app> — админка целиком (роутинг по #hash)
  js/components/       <cqa-case> — карточка кейса, самостоятельный веб-компонент
  js/pages/            обзор, диалоги, апелляции, чек-листы, точность
backend/
  app.py               FastAPI: диалоги, чек-листы, запуск оценки, апелляции, статистика
  evaluator.py         промпт, вызов Claude, проверка ответа (номера реплик, цитаты, N/A)
  scoring.py           итог: веса, перераспределение при N/A, секции, грубые ошибки, округление
  db.py                SQLite (data/cqa.db), документы в JSON
```

**Оценка.** Реплики нумеруются `[N]`. Модель видит описание каждого критерия, шкалу, правило N/A и правило грубой ошибки. Реплики бота и системные события идут как контекст, оценивается только оператор. Ответ модели проверяется:
- номера реплик должны существовать;
- цитаты сверяются с текстом реплики, а если не совпадают, заменяются на текст реплики;
- N/A принимается только там, где он разрешён;
- значение приводится к шкале.

**Итог считается в коде, а не моделью.** Значение шкалы переводится в долю (`(v − min)/(max − min)`) и умножается на вес. Вес N/A-критериев перераспределяется между применимыми. Секции считаются так же. Округление и порог задаются в чек-листе. Грубая ошибка либо отмечается отдельно, либо обнуляет итог, это тоже настройка чек-листа.

**Версии чек-листа.** Каждое сохранение создаёт новую неизменяемую версию, которая сразу становится активной. Каждая оценка ссылается на версию, по которой сделана, поэтому старые результаты не ломаются при правке критериев. В карточке можно переключаться между оценками разных версий.

**Апелляции оформляются по отдельному критерию.** Хранятся исходная оценка ИИ, комментарий, решение проверяющего с причиной и итог до и после. В карточке видны все три состояния: ИИ, решение и финал.

## Сценарий демо (5 минут)

1. **Интерфейс и диалог.** «Диалоги» → фильтр по языку → открыть диалог.
2. **Оценка.** Слева транскрипт, справа итог, секции и критерии. Клик по критерию или по `[N]` прокручивает к реплике и подсвечивает её. Для пропущенного действия есть «Проверенный участок». Показать критерий с N/A: его причину и перераспределённый вес. У звонка есть кнопка «Открыть плеер» и метки `+мм:сс` от начала записи.
3. **Апелляция.** «Оспорить критерий» → комментарий → «Апелляции» → «Изменить оценку» → причина → итог пересчитан (`было → стало`). В карточке видны оценка ИИ, решение и финал.
4. **Смена критерия.** «Чек-листы» → удалить или заменить критерий (или вставить JSON) → «Сохранить новую версию» → «Запустить оценку» → прогресс на «Диалогах».

**Экспорт результатов:** «Точность» → CSV или JSON (ответ по каждому критерию, обоснование, доказательства, итог, грубые ошибки).

**Сдача результатов (формат организаторов, JSON 1.0):** при запущенном сервисе
```sh
python3 scripts/export_results.py DEV              # → results/dev/results.json
python3 scripts/export_results.py <group_id> prod  # → results/prod/results.json (ровно 10 записей)
```
Коды критериев переводятся в коды организаторов (`discovery`, `dialogue`, `closure`, `critical`), N/A → `null`, номера реплик — с 1. Неоценённые диалоги попадают как `status: "error"` с причиной; скрипт печатает все проблемы. То же — кнопка **results.json** на странице «Точность». Название команды — `CQA_TEAM_NAME`.

**Контроль на 23-м часу:** «Из API организаторов» → `group_id` контрольного набора → «Оценить» → «Только неоценённые».

## Встраивание в Dynamics 365

Интерфейс собран из веб-компонентов без фреймворка и сборки. Все стили ограничены `cqa-app`, а адрес сервиса задаётся атрибутом. Подключите `frontend/css/app.css` и `frontend/js/app.js` как web resources и вставьте:

```html
<cqa-app api-base="https://cqa.example.com"></cqa-app>
<!-- или только карточку на форме обращения: -->
<cqa-case dialog-id="p1-ru-001" api-base="https://cqa.example.com"></cqa-case>
```
