# CQA — Conversation Quality Analytics

Оценка качества диалогов контакт-центра Freedom Broker по чек-листу. Чаты и звонки на RU/KZ/EN, по каждому критерию балл, обоснование и ссылки на реплики. Оценку можно оспорить по отдельному критерию, проверяющий выносит решение, итог пересчитывается.

## Запуск

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # заполнить CQA_SOURCE_URL и ANTHROPIC_API_KEY
./run.sh                # http://127.0.0.1:8000
```

Без `ANTHROPIC_API_KEY` оценка идёт через `claude -p`, если установлен Claude Code.

При первом запуске создаётся чек-лист по умолчанию. DEV-набор берётся из `data/dev.json`, если файл есть (в git его нет). Новые наборы, в том числе контрольный, грузятся на странице «Диалоги» кнопкой «Из API организаторов» по `group_id`.

## Тесты

```sh
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
```

Тесты работают на временной базе с мок-оценщиком, ключ и сеть не нужны. Проверяются расчёт итога (веса, N/A, округление, грубые ошибки), разбор ответа модели и голосование, маскирование ПДн, все эндпоинты API и импорты JS. В GitHub Actions запускаются на каждый пуш.

## Модель

Claude Opus 5.5 (`claude-opus-5-5`), adaptive thinking, `effort=high`, ответ по JSON-схеме.

- Чек-лист организаторов хранится как конфигурация: 8 критериев, шкалы 0/5/10/15/20 и 0/4/7/10, флаг грубых ошибок. Памятка со стр. 3 PDF тоже в чек-листе и уходит в промпт.
- Время первой реакции и ожидания дольше 3 минут считаем по меткам времени сами и передаём модели готовыми.
- Каждый диалог оценивается 3 раза (`CQA_SAMPLES`), по критерию берём ответ большинства, при ничьей на шкале — медианную ступень. Если прогоны разошлись, критерий помечается на проверку.
- Ответ модели проверяем: значение приводим к ступени шкалы, N/A только там, где разрешён, номера реплик и цитаты сверяем с транскриптом.
- На странице «Точность» можно загрузить эталон (JSON/CSV) или отправить туда проверенную оценку и посмотреть совпадение по критериям и расхождения по диалогам.

Один диалог (3 прогона) стоит примерно $0.15–0.30, 10 диалогов — $2–3. Фактические токены, стоимость и время видны в карточке и на «Обзоре».

## Структура

```
frontend/              HTML/CSS/JS без сборки
  js/app.js            <cqa-app>, вся админка (роутинг по #hash)
  js/components/       <cqa-case>, карточка кейса
  js/pages/            обзор, диалоги, апелляции, чек-листы, точность
backend/
  app.py               FastAPI: диалоги, чек-листы, оценка, апелляции, статистика
  evaluator.py         промпт, вызов модели, проверка ответа
  scoring.py           расчёт итога
  db.py                SQLite (data/cqa.db)
```

Реплики в промпте нумеруются `[N]`. Бот и системные события идут как контекст, оценивается только оператор.

Итог считает код, не модель: значение шкалы переводится в долю `(v − min)/(max − min)` и умножается на вес, вес N/A-критериев делится между остальными. Округление, порог и то, обнуляет ли грубая ошибка итог, задаются в чек-листе.

Каждое сохранение чек-листа создаёт новую версию. Оценка привязана к версии, так что старые результаты не ломаются после правки критериев.

Апелляция подаётся на один критерий. Хранятся оценка модели, комментарий, решение проверяющего с причиной и итог до/после.

## Экспорт и сдача результатов

На странице «Точность» есть выгрузка в CSV и JSON.

results.json в формате организаторов (сервис должен быть запущен):
```sh
python3 scripts/export_results.py DEV              # results/dev/results.json
python3 scripts/export_results.py <group_id> prod  # results/prod/results.json, 10 записей
```
Коды критериев переводятся в коды организаторов (`discovery`, `dialogue`, `closure`, `critical`), N/A пишется как `null`, реплики нумеруются с 1. Неоценённые диалоги попадают со `status: "error"`. То же делает кнопка results.json на «Точности». Название команды задаётся в `CQA_TEAM_NAME`.

## Встраивание в Dynamics 365

Веб-компоненты без фреймворка, стили ограничены `cqa-app`, адрес сервиса задаётся атрибутом. Подключить `frontend/css/app.css` и `frontend/js/app.js` как web resources:

```html
<cqa-app api-base="https://cqa.example.com"></cqa-app>
<!-- или только карточка на форме обращения -->
<cqa-case dialog-id="p1-ru-001" api-base="https://cqa.example.com"></cqa-case>
```
